Overview & architecture

This Flask application provides a lightweight search front-end, an images service with multi-engine fallback, a placeholder image generator (fetch + cache), and an AI chat proxy that calls an OpenAI-compatible inference endpoint hosted by GitHub Models.

Primary components:

  • Routes: HTML pages (index, images, placeholder) and JSON APIs (/api/search, /ai).
  • Image scrapers: DuckDuckGo, Bing, Google, Brave.
  • Cache / storage: local filesystem for downloaded placeholders (configurable directory).
  • AI: `openai.OpenAI` client configured to use a GitHub Models inference endpoint.

Authentication & rate-limiting notes

The application as provided uses a plain GitHub PAT stored in environment variables (e.g. GITHUB_TOKEN). Important: never commit secrets to source control. For production:

  • Use a secrets manager (Vault, AWS Secrets Manager, Cloudflare KV with encryption).
  • Move rate-limiting and authentication to a reverse proxy (Cloudflare or Nginx with limiting rules) or implement Flask-Limiter.
  • Consider adding an API key layer for /api/search and /ai to avoid abuse.

Endpoints reference

/ — Search page (HTML)

Method: GET

Query parameters:

ParameterTypeDefaultDescription
qstring""Search query text. Rendered in index.html and used by main(q, page).
pageinteger1Pagination page for the search results (validated to be >=1).
bbinary string""Optional: a UTF-8 text encoded as binary via utf8_string_to_binary. If present and q is empty, the app decodes b to a query and redirects. If q present and b empty, it encodes q to binary and redirects. This is a UX convenience for copy-pasting binary values.

Behavior:

  1. If q is provided and b is empty the app encodes q and redirects to the same route with b set.
  2. If b provided and q empty the app decodes b back to text and redirects.
  3. If q present: it calls main(q, page) (external module import) to obtain a list of results and renders index.html.

Example (human):

GET /?q=python+flask&page=1

/api/search — JSON Search API

Method: GET

This route returns JSON-formatted search results and a small pagination block.

Request parameters:

ParameterTypeRequiredDescription
qstringyesSearch query. If missing, returns HTTP 400.
pageintegernoPage number, defaults to 1. Minimum 1.

Successful response (HTTP 200):

{
  "results": [ /* array returned from main(q,page) */ ],
  "query": "...",
  "page": 1,
  "has_next": true | false,
  "has_prev": true | false,
  "total_results": 10
}

Error responses:

  • 400 — Missing q parameter: {"error":"Missing query parameter 'q'"}
  • 500 — Internal errors propagated from main().

Example (curl):

curl "https://sodeom.com/api/search?q=flask+scrape&page=1"

/ai — AI Chat Proxy

Methods: GET, POST

Purpose: a thin proxy to an OpenAI-compatible chat completion API (configured to use GitHub Models endpoint via OpenAI(base_url=GITHUB_ENDPOINT)).

Parameters & body:

  • query (query string) — the user prompt (required when missing a JSON body with messages).
  • POST body (JSON, optional) — used to pass model, messages, temperature, etc. If messages not provided, the endpoint will build a default messages array with a system message and the query as the user message.

Important notes:

  • The server uses DEFAULT_MODEL (openai/gpt-4.1-mini) unless overridden in the JSON body.
  • Request flow: constructs or uses provided messages → calls client.chat.completions.create(**other_params) → returns {"answer": }.

Responses:

// Success (200)
{ "answer": "...generated text..." }

// Error (400)
{ "error": "No query provided" }

// Error (500)
{ "error": "" }

Example (curl):

curl -G "https://sodeom.com/ai" --data-urlencode "query=Explain+Flask+blueprints"

# Or with JSON body
curl -X POST "https://sodeom.com/ai?query=hi" -H "Content-Type: application/json" -d '{"model":"openai/gpt-4.1-mini","messages":[{"role":"user","content":"Say hi"}]}'

Security & cost: Be aware that proxied requests consume the configured upstream quota (GitHub Models). Log and rate-limit this endpoint in production.

/images — Images page (HTML)

Method: GET

Parameters:

ParameterTypeRequiredDescription
qstringnoSearch query to fetch images from multiple engines.
pageintegernoPagination page number (>=1).

Behavior: If q is provided, fetch_images_with_fallback(q,page) is called and results rendered in images.html. The fallback sequence is: DuckDuckGo → Bing → Google → Brave.

Example:

GET /images?q=kitten&page=1

/placeholder & /placeholder/url — Downloadable placeholder images

Method: GET

Two endpoints are provided:

  • /placeholder?q=<query>&page=<n> — returns a binary image file (downloaded and cached locally). If the app cannot fetch any image for the query, it serves a local fallback at static/not-found.png.
  • /placeholder/url?q=<query>&page=<n> — returns the first candidate image URL (string) or the fallback path if none found.

Flow (for /placeholder):

  1. Call fetch_images_with_fallback(q,page) to get candidate image URLs.
  2. Loop through candidates and call install_image(url) which downloads the image and saves it to placeholders/ using a SHA1 hash filename.
  3. If a valid image is downloaded, return it with the correct MIME type. If none succeeded, return the built-in fallback PNG.

Example:

GET /placeholder?q=puppy&page=1
# Downloads a cached image and returns a binary response

Notes:

  • The install_image function checks the upstream response Content-Type and only saves image/* responses.
  • Images are stored in placeholders/ by SHA1(url). Existing files are reused to avoid re-downloading.

Image sourcing & fallback strategy

Sodeom uses four sources in order: DuckDuckGo, Bing, Google, Brave. The function fetch_images_with_fallback tries each engine in sequence and filters out obvious NSFW keywords from URLs.

Engine-specific notes

  • DuckDuckGo: Uses vqd token and a JSON endpoint (/i.js). The code extracts the vqd token from the search results page, then calls the JSON endpoint for images.
  • Bing: Scrapes a.iusc elements and parses the m attribute for murl.
  • Google: Uses inline AF_initDataCallback blocks and extracts JPG links (fragile — Google frequently changes markup). Use of the Google scraping method may break and should be replaced with an official API for reliability.
  • Brave: Calls Brave's public image JSON endpoint (/api/images), which is convenient but may be rate limited.

Filtering: Basic URL keyword filtering is used for NSFW terms; for production you should also add content-based filtering (image moderation) and stricter safe-search parameters when calling provider APIs.

Implementation details & helper functions

utf8_string_to_binary / binary_to_utf8_string

Utility functions convert UTF-8 strings to a binary string (bitstream) and back. The binary string is padded to multiples of 64 bits when encoding; the decoder strips trailing zero bytes. The functions are used to let users copy queries as binary and roundtrip them via the b query parameter on the root route.

install_image

Downloads a remote image to placeholders/ using a SHA1(url). It verifies the upstream Content-Type header begins with image/ and streams the response to disk to avoid loading large images into memory. Timeout and error handling are present but basic — consider retry/backoff and more granular error handling for production.

HEADERS

All scrapers use a common browser-like User-Agent header to reduce blocking and to get consistent results from search engines.

Errors & common failure modes

  • Network errors: Requests to external engines or the AI backend may timeout (timeout=10). Increase timeouts or add retries for reliability.
  • Parsing failures: Scrapers rely on fragile HTML structures — any change upstream can cause empty results.
  • Upstream quota: The GitHub Models endpoint / OpenAI model may fail for auth or quota reasons; surface clear messages to clients and log exceptions.
  • Image MIME mismatches: Some providers set incorrect content-type headers; install_image rejects responses not starting with image/ to avoid saving HTML error pages as images.

Security & hardening recommendations

  1. Remove hard-coded tokens. Use os.environ and secrets managers.
  2. Protect /ai and /api/search behind an API key or OAuth; add rate-limiting (Flask-Limiter) and logging/monitoring.
  3. Sanitize and validate any user-supplied URLs or binary payloads before use.
  4. Run scrapers behind a proxy that rotates IPs or use official APIs to avoid being blocked.
  5. Serve the app with a production WSGI server (Gunicorn/uvicorn) and put a caching layer (Redis) in front of expensive operations.
